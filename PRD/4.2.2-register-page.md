**Существующий use case** `App\Application\User\RegisterUser::execute($name, $email, $plainPassword): User`:
- Бросает `WeakPasswordException` (пароль короче 8), `InvalidArgumentException` (пустое имя / невалидный email), `EmailAlreadyTakenException` (дубликат email).
- Email нормализуется (lowercase + trim) перед поиском дубликатов.
- Возвращает полную `User` entity после save.

## Scope

### 1. `GET /register` — `RegisterController::show`
- Рендерит `resources/views/auth/register.blade.php` (новый view).
- Если пользователь уже залогинен — редирект на `/` (пока) или 302 на Dashboard (появится в 7.1). Для 4.2.2 редирект на `/`.

### 2. `POST /register` — `RegisterController::store`
- Принимает `name`, `email`, `password`, `password_confirmation`.
- Laravel `FormRequest` (`RegisterRequest`) для базовой валидации формы: `required`, `min:8` на password, `confirmed`, `email` формат. Эти проверки **дублируют** domain-валидацию — это сознательно, Laravel валидация даёт читаемые error-сообщения до вызова use case.
- Вызывает `RegisterUser::execute`. Оборачивает exceptions в Laravel ValidationException с привязкой к полю:
  - `EmailAlreadyTakenException` → ошибка на поле `email`.
  - `WeakPasswordException` → ошибка на поле `password` (подстраховка, обычно ловится FormRequest).
  - `InvalidArgumentException` → re-throw (500, это программная ошибка).
- После успешной регистрации: `SessionGuard::login($user->id)` + redirect на `/` (временно; в 7.1 будет `/dashboard`).

### 3. View `resources/views/auth/register.blade.php`
- Внутри `<x-layouts.app>`.
- Форма POST `/register` с CSRF.
- Поля через `<x-form-field>`: Name, Email, Password, Confirm Password.
- Кнопка submit через `<x-button>`.
- Выводит `$errors` из ValidationException через `<x-form-field :error="$errors->first('name')">`.

### 4. Routes
Добавить в `routes/web.php`:
```php
Route::get('/register', [RegisterController::class, 'show'])->name('register');
Route::post('/register', [RegisterController::class, 'store']);
```

### 5. Nav обновление
В `components/nav.blade.php` — `@guest` ссылка «Register» теперь использует `route('register')` вместо `#`. Welcome page — аналогично.

### 6. Feature тесты — `tests/Feature/Web/Auth/RegisterTest.php`
- `it('shows the registration form for guests')` — GET `/register` → 200, форма с полями.
- `it('redirects authenticated users away from the registration form')` — login → GET `/register` → 302 на `/`.
- `it('registers a new user and logs them in')` — POST валидные данные → 302 на `/`, пользователь в БД, `SessionGuard::currentUserId()` совпадает с новым id.
- `it('rejects registration with invalid name')` — пустое имя → 422 / редирект обратно с ошибкой.
- `it('rejects registration with invalid email')` — невалидный email → ошибка на поле email.
- `it('rejects registration with short password')` — 7 символов → ошибка на поле password.
- `it('rejects registration with mismatched password confirmation')` — confirmed валидация.
- `it('rejects registration with duplicate email case-insensitively')` — второй раз `ALICE@example.COM` при существующем `alice@example.com` → ошибка на email.

## Вне scope
- Email verification (не в MVP, см. prd-taskflow §7).
- Remember me / долговечные токены.
- Password complexity rules beyond minimum length.
- i18n валидационных сообщений.
