# PRD 1.r1 — Инвариант `updatedAt >= createdAt`

## Источник
Codex review задачи 1.2 (см. AssumptionLog 1.2). Замечание помечено как `defer` и вынесено в Roadmap как `1.r1 [review]`. Должно применяться симметрично ко всем доменным сущностям, у которых есть оба поля.

## Цель
Добавить инвариант: `updatedAt >= createdAt` в конструкторы доменных сущностей. Это закрывает класс багов, при которых сущность могла быть собрана с временными метками вне физически возможного порядка (например, ошибка в маппере или регрессия в use case).

## Scope

### В scope
- `App\Domain\User\User` — есть `createdAt` и `updatedAt`
- `App\Domain\Project\Project` — есть `createdAt` и `updatedAt`
- `App\Domain\Task\Task` — есть `createdAt` и `updatedAt`

Поведение инварианта:
- Бросать `InvalidArgumentException` с сообщением вида `<Entity> updatedAt must not be earlier than createdAt`, если `updatedAt < createdAt`.
- Равенство (`updatedAt == createdAt`) допустимо — соответствует начальному состоянию (новая сущность).
- Сравнение через `format('U.u')` (instant + microseconds, UTC), чтобы не зависеть от timezone metadata. Симметрично с `DueDate::equals` (см. AssumptionLog 1.6).

### Вне scope
- `ProjectMember` — у него только `createdAt`, поля `updatedAt` нет.
- `Comment` — то же, comments иммутабельны (см. AssumptionLog 1.5).
- Доработка `with*` мутаторов — они уже идут через конструктор, инвариант сработает автоматически на новых временных метках.

## Декомпозиция
Одна подзадача: 3 entity + тесты + правки существующих фикстур, если потребуется.

Оценка: ~60 строк кода + ~30 строк тестов. В лимит ≤150 строк укладывается.

## Тесты (Red → Green)
Для каждой из трёх entity (User/Project/Task) добавить негативный тест:
- `it('rejects updatedAt earlier than createdAt')` — `createdAt = T`, `updatedAt = T-1s` → `InvalidArgumentException`.

Позитивный кейс `updatedAt == createdAt` уже покрыт существующими позитивными тестами (где обе метки берутся из `$now`).

## Обратная совместимость
- Существующие фикстуры тестов используют либо `$now` для обеих меток, либо `created < updated` (в `with*` тестах) — все валидны.
- Существующий `EloquentUserRepositoryTest` ставит `updatedAt = newUpdatedAt > createdAt` — валидно.
- Маппер `UserMapper` (3.2.2) читает `created_at`/`updated_at` из БД — БД гарантирует физический порядок (Laravel `timestamps()`), регрессий не ожидается.

## Definition of Done
- 3 entity отвергают `updatedAt < createdAt` с понятным сообщением.
- 3 негативных теста (по одному на entity).
- `composer check:all` зелёный.
- Self-review, Codex review (полный шаблон), триаж, push, CI.
