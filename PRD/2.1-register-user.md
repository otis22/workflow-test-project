# PRD: 2.1 — Use case RegisterUser

## Цель

Application use case `RegisterUser`: валидация, хэширование пароля, сохранение нового пользователя в репозитории. Без зависимостей от Laravel.

## Зависимости (новые интерфейсы)

- `App\Application\Clock\Clock` — `now(): DateTimeImmutable`. Используется всеми use cases для timestamps без хардкода.
- `App\Application\Hashing\PasswordHasher` — `hash(string $plain): string`, `verify(string $plain, string $hash): bool`. Адаптер реализуется в Infrastructure (3.x).
- `App\Domain\User\UserRepository` — interface с методами:
  - `findByEmail(string $email): ?User`
  - `save(User $user): User` — возвращает entity с присвоенным id

## Контракт RegisterUser

```php
final readonly class RegisterUser
{
    public function __construct(
        private UserRepository $users,
        private PasswordHasher $hasher,
        private Clock $clock,
    ) {}

    public function execute(string $name, string $email, string $plainPassword): User;
}
```

### Правила

- Если пользователь с таким email уже существует — `EmailAlreadyTakenException` (Application/Exception).
- Минимальная длина пароля — 8 символов. Иначе `WeakPasswordException`.
- Email и name валидируются конструктором User entity (re-use доменной валидации).
- Пароль хэшируется через `PasswordHasher`, plain-password дальше не проходит.
- `createdAt`/`updatedAt` берутся из `Clock::now()`.
- id для нового User: до save = 0 (placeholder), после save репозиторий присваивает реальный.

## Тесты

- Создаёт пользователя при валидных данных, возвращает entity с id из репозитория
- Бросает `EmailAlreadyTakenException` если findByEmail вернул пользователя
- Бросает `WeakPasswordException` если пароль <8 символов
- Re-throws InvalidArgumentException из конструктора User для невалидного email
- Хэширует пароль перед сохранением (passwordHash != plain)
- Использует Clock для createdAt/updatedAt
