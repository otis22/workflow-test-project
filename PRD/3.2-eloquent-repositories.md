# PRD: 3.2 — Eloquent модели и репозитории

## Цель

Реализовать инфраструктурный слой persistence: Eloquent-модели для 5 доменных таблиц + конкретные реализации 5 доменных репозиториев + биндинг интерфейсов через Service Provider. После этого можно будет запускать application use cases поверх реальной PostgreSQL вместо InMemory-фейков.

## Контекст

- Доменные интерфейсы уже существуют (stage 2): `UserRepository`, `ProjectRepository`, `ProjectMemberRepository`, `TaskRepository`, `CommentRepository`.
- Миграции готовы (3.1).
- Чистая архитектура: **доменные сущности не знают про Eloquent**. Репозиторий принимает domain entity, маппит в Eloquent-модель, сохраняет; при load — обратный маппинг. Eloquent-модели и mappers живут в `app/Infrastructure/Persistence/Eloquent/`.

## Scope

**В scope:**

- 5 Eloquent-моделей в `app/Infrastructure/Persistence/Eloquent/Model/`: `UserModel`, `ProjectModel`, `ProjectMemberModel`, `TaskModel`, `CommentModel`.
  - `$table` явный (имя из миграции 3.1)
  - `$guarded = []` — маппер контролирует поля
  - Casts для timestamps и enum-полей (для Status/Priority используем string cast, enum-конверсия — в mapper'е, чтобы домен не утёк в model)
- 5 mappers (один per aggregate): `UserMapper`, `ProjectMapper`, `ProjectMemberMapper`, `TaskMapper`, `CommentMapper` с методами `toDomain(Model): Entity` и `toRow(Entity): array`.
- 5 Eloquent-репозиториев, реализующих доменные интерфейсы, в `app/Infrastructure/Persistence/Eloquent/`:
  - `EloquentUserRepository`
  - `EloquentProjectRepository`
  - `EloquentProjectMemberRepository`
  - `EloquentTaskRepository` (включая `listByProject` с фильтрами status/dueBefore и `listByAssignee`)
  - `EloquentCommentRepository`
- Новый `PersistenceServiceProvider` (регистрируется в `bootstrap/providers.php`) биндит каждый доменный интерфейс к Eloquent-реализации через `$this->app->bind(...)`.
- Feature test на каждый репозиторий: round-trip через реальную БД (`RefreshDatabase`).

**Вне scope:**

- Фабрики и сидеры (3.3).
- Оптимизация запросов (индексы уже в 3.1).
- Транзакции — использовать там, где несколько save подряд (CreateProject), но это в application layer (use case); инфраструктурные репо не управляют транзакциями.
- Eager loading — read use cases пока не требуют join'ов.

## Маппинг доменных типов ↔ DB

- `DateTimeImmutable` ↔ `timestamp` — Eloquent автоматически через casts `datetime`. В mapper конвертация: `$model->created_at?->toDateTimeImmutable()` (Carbon → DateTimeImmutable).
- `Status` enum ↔ `enum` column — `$model->status = $entity->status->value`; `Status::from($model->status)`.
- `Priority` — аналогично.
- `DueDate` value object ↔ nullable `timestamp` — `$model->due_date = $entity->dueDate?->value`; `$model->due_date !== null ? new DueDate($model->due_date->toDateTimeImmutable()) : null`.
- `passwordHash` (camelCase) ↔ `password_hash` (snake_case) — вручную в mapper, чтобы не плодить Eloquent-магию.
