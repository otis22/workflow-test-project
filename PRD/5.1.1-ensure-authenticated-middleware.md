# PRD 5.1.1 — EnsureAuthenticated middleware

## Источник
Roadmap 5.1 декомпозирован: 5.1.1 — инфраструктурное middleware для защиты authenticated routes, 5.1.2 — сам список проектов. Middleware требуется для 5.1.2+ (ProjectsController), 5.2 (создание проекта), 5.3 (страница проекта), 6.x, 7.x.

- «Гость: может зарегистрироваться и войти.»

**`artifacts/ui-spec-taskflow-ru.md` §4:**

- Навигация подразумевает, что все экраны кроме login/register требуют авторизации.

**Существующий порт** `App\Application\Auth\SessionGuard`:
- `currentUserId(): ?int` — единственный источник истины для «залогинен ли».
- Laravel дефолтный `auth` middleware использует Laravel `Auth` facade, которая **не привязана** к нашему порту (см. AssumptionLog 4.4).

## Scope

### 1. `App\Http\Middleware\EnsureAuthenticated`
- Конструктор принимает `SessionGuard` (DI).
- `handle(Request $request, Closure $next)`:
  - Если `$this->guard->currentUserId() === null` — `redirect()->guest(route('login'))`. Метод `guest()` запоминает intended URL, чтобы после login вернуть пользователя.
  - Иначе `return $next($request)`.
- Финальный класс, `readonly`.

### 2. Alias в `bootstrap/app.php`
```php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->alias([
        'auth.session' => EnsureAuthenticated::class,
    ]);
})
```

Алиас `auth.session` — отличается от Laravel `auth`, чтобы не путать с default guard.

### 3. Feature тесты — `tests/Feature/Http/Middleware/EnsureAuthenticatedTest.php`
Для изоляции middleware тестируется на ad-hoc route, регистрируемом в самом тесте.
- `it('redirects guests to the login page')` — GET с применённым middleware → 302 `/login`.
- `it('passes through authenticated requests')` — login через `SessionGuard` → GET → 200 с ожидаемым телом.
- `it('remembers the intended URL for redirect-after-login')` — GET как guest → после редиректа `session()->get('url.intended')` содержит исходный URL.

## Вне scope
- Реальные authenticated routes (5.1.2+).
- CSRF/rate limit — отдельные middleware.
- Redirect-to-intended после login — логика в LoginController появится отдельно если понадобится (4.3 не делает intended redirect, пока всегда `/`).
