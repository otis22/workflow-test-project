# PRD: 2.11 — Отложенный Codex review задач 2.2–2.10

## Контекст

На этапе 2 Codex плагин был недоступен из-за rate limit (см. `AssumptionLog.md` §"Этап 2 — отклонение от workflow"). Задачи 2.2–2.10 прошли расширенный self-review, но без полноценного Codex-цикла. Задача 2.11 закрывает этот долг: прогнать Codex review задним числом и зафиксировать триаж.

## Цель

Провести Codex review на diff application-слоя (задачи 2.2–2.10), классифицировать замечания (accept/defer/reject), при наличии `accept` — оформить как новые задачи `[review]` в Roadmap (не править текущий scope 2.11), зафиксировать результат в `AssumptionLog.md`.

## Scope

**В scope:**
- Codex review на diff `e0f419c^..ad08bdd` (коммиты задач 2.2–2.10, исключая уже отревьюенную 2.1).
- Триаж замечаний по workflow §5, шаг 9.
- Запись результата в `AssumptionLog.md` §"2.11".
- Создание новых задач `[review]` в `Roadmap.md` для принятых замечаний (category `accept` → отдельная задача, т.к. scope 2.11 = только review, не исправления).

**Вне scope:**
- Фактическое исправление замечаний (оформляются как отдельные задачи 2.r2, 2.r3, …).
- Повторный review уже отревьюенной 2.1.

## Фокус review

Для каждой задачи 2.2–2.10:
- Соответствие PRD подзадачи
- Соответствие артефактам (доменная модель, техтребования)
- Security: авторизация, валидация, boundary-кейсы
- Архитектура: чистота слоёв, DI через порты, отсутствие утечек инфраструктуры
- Тесты: покрытие правил, негативные кейсы

## Ограничения

- **Бюджет Codex review: максимум 2 прогона** (согласно AGENTS.md §5 шаг 10). Второй прогон — только если после первого появляются правки, требующие верификации.
- Поскольку 2.11 не вносит code changes, планируется **1 прогон** review. Второй резервируется на случай обнаружения систематических проблем, требующих повторной проверки части diff'а.
