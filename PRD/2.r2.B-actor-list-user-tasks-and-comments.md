# PRD 2.r2.B — Actor authorization для ListUserTasks и ListTaskComments

## Источник
Codex review 2.11. Roadmap `2.r2 [review]`. Продолжение 2.r2.A.

## Scope

### `App\Application\Task\ListUserTasks`
- **Семантическое переименование** `int $userId` → `int $actorId`. Контракт use case: «вернуть задачи актёра, который вызывает». Use case всегда работает только с identiteit самого актёра — никаких «получить задачи другого пользователя».
- Никакой membership-проверки не требуется: параметр **есть** identity актёра.
- Authorization «actor действительно тот, за кого себя выдаёт» — ответственность session layer (вне scope use case).
- Тесты: переименовать переменные/комментарии, добавить doc-комментарий контракта над методом. Поведение не меняется.

### `App\Application\Task\ListTaskComments`
- Добавить первым параметром `int $actorId`.
- Логика:
  1. `findById($taskId)` — если нет, `TaskNotFoundException::forId($taskId)`.
  2. Проверить, что `actorId` — член `$task->projectId`. Если нет — `NotAProjectMemberException`.
  3. Вернуть `comments->listByTask($taskId)`.
- Новые зависимости: `TaskRepository` и `ProjectMemberRepository` инъецируются в конструктор.
- **Замечание про 404 vs 403 leak** (Codex review 2.r2.A) — этот use case подвержен той же проблеме. Решение симметрично 2.r2.A: defer в `2.r3 [review]` (одна задача покрывает оба use case).
