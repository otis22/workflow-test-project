**Существующий use case** `App\Application\Auth\Login::execute($email, $plainPassword): User`:
- Ищет по нормализованному email (lowercase + trim, 2.r1).
- Бросает `InvalidCredentialsException` с сообщением `'Invalid credentials'` для unknown email И wrong password (no user enumeration, см. AssumptionLog 2.2).
- **Сам вызывает `$this->session->login($user->id)`** — контроллер НЕ должен повторять этот вызов.
- Возвращает `User` entity.

## Scope

### 1. `GET /login` — `LoginController::show`
- Рендерит `resources/views/auth/login.blade.php`.
- Если уже залогинен — redirect `/` (симметрично 4.2.2).

### 2. `POST /login` — `LoginController::store`
- `LoginRequest` FormRequest с `email` (required, email) и `password` (required, string). **Без** `min:8` — чтобы не раскрывать полное правило и не дублировать domain-guard; достаточно `required`.
- Вызывает `Login::execute($request->input('email'), $request->input('password'))`.
- `InvalidCredentialsException` → `ValidationException::withMessages(['email' => 'Invalid credentials.'])` — ошибка на поле `email` (общая форма).
- Успех: `Login::execute` сам логинит в `SessionGuard`; контроллер делает `redirect('/')` (Dashboard в 7.1).

### 3. View `resources/views/auth/login.blade.php`
- Внутри `<x-layouts.app>`.
- Форма POST `/login` с CSRF.
- Поля: Email, Password через `<x-form-field>`.
- `<x-button type="submit">`.
- Выводит `$errors->first('email')`.

### 4. Routes
```php
Route::get('/login', [LoginController::class, 'show'])->name('login');
Route::post('/login', [LoginController::class, 'store']);
```

### 5. Nav обновление
`components/nav.blade.php`: `@guest` → «Sign in» теперь использует `route('login')` (вместо `#`). `welcome.blade.php` — аналогично.

### 6. Feature тесты — `tests/Feature/Web/Auth/LoginTest.php`
- `it('shows the login form for guests')` — GET `/login` → 200, форма с email/password.
- `it('exposes the login route link from the home page')` — `/` содержит `route('login')`.
- `it('redirects authenticated users away from the login form')` — auth → GET `/login` → 302 `/`.
- `it('logs in with correct credentials and redirects')` — регистрация через use case, затем POST с корректными данными → 302 `/`, `SessionGuard::currentUserId()` = id.
- `it('logs in with case-insensitive email')` — регистрация `alice@example.com`, login `'ALICE@Example.COM'` → успех.
- `it('rejects unknown email with generic error')` — `ghost@example.com` → ошибка на email с общим сообщением.
- `it('rejects wrong password with same generic error')` — проверяет, что сообщение одинаковое (no user enumeration).
- `it('rejects empty email')` — FormRequest required.
- `it('rejects empty password')` — FormRequest required.

## Вне scope
- Remember me / долговечные токены (не в MVP).
- Two-factor authentication.
- Rate limiting / brute force защита — вынесено в отдельный задачу финального этапа или в review.
- Dashboard как destination — пока `/`, исправим в 7.1.

## Оценка
