# 2026-03-29 — Этап 1. Базовое окружение и каркас проекта

## Допущения

- Для локальной разработки выбран Laravel 13 на PHP 8.4, так как стек из артефактов допускает совместимые стабильные минорные версии поверх требования `PHP 8.3+`.
- Для локальной базы данных выбран PostgreSQL как реляционная СУБД для dev и CI окружения.
- Для duplicate detection выбран `jscpd` как совместимый аналог `PHPCPD`, потому что `sebastian/phpcpd` не совместим с текущей связкой PHP 8.4 и PHPUnit 12.

## Неясности

- Полный mutation/e2e контур остаётся отдельной задачей следующих этапов roadmap и в этапе 1 не доводился до рабочего состояния.

## Архитектурные решения

- Локальная среда собрана из трёх сервисов: `app` (PHP-FPM + Composer + Node), `web` (Nginx) и `db` (PostgreSQL).
- Базовые quality checks вынесены в `composer` scripts и основной workflow `.github/workflows/ci.yml`.
- Для smoke test на этапе bootstrap корневой маршрут упрощён до текстового ответа, чтобы не зависеть от дальнейшей UI-реализации MVP.

## Итог review этапа

- Артефакты этапа синхронизированы: `Roadmap.md`, `PRD/001-stage-1-bootstrap.md`, `README.md`, `CHANGELOG.md`.
- Локальный smoke test зелёный: `docker compose up -d`, `curl -fsS http://localhost`.
- Локальный quality contour зелёный: `docker compose exec -T app composer qa:ci`.

# 2026-03-29 — Этап 2. Архитектурные границы и домен

## Допущения

- На этапе 2 доменная модель реализована как чистые PHP-объекты без привязки к Eloquent, даже если в проекте уже существует Laravel user model для будущей web/persistence интеграции.
- Для application тестов достаточно in-memory репозиториев в infrastructure слое до появления реальной persistence-реализации на следующих этапах.

## Неясности

- Переходы статусов задач пока оставлены гибкими; домен фиксирует набор допустимых статусов, но не вводит отдельную матрицу переходов до появления более детальных требований.
- История изменений задач остаётся вне этапа 2 и будет определяться в более поздних задачах, если это потребуется.

## Архитектурные решения

- Доменные правила вынесены в `app/Domain`, use cases и порты репозиториев — в `app/Application`, тестовые in-memory адаптеры — в `app/Infrastructure`.
- Coverage gate ограничен `app/Domain` и `app/Application`, что соответствует техтребованию по приоритетному покрытию domain/application слоёв.
- Правила проекта реализованы через инварианты в доменных сущностях: владелец автоматически становится участником, creator/assignee/comment author должны быть участниками проекта.

## Итог review этапа

- Структура слоёв соответствует артефактам и не вносит зависимости domain/application от HTTP или Eloquent.
- Локальный smoke test остаётся зелёным: `curl -fsS http://localhost`.
- Локальный quality contour зелёный: `docker compose exec -T app composer qa:ci`.
