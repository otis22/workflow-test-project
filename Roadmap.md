# Roadmap: TaskFlow MVP

## Этап 1: Инфраструктура проекта

- [x] 1.1 Инициализация Laravel-проекта — создать Laravel-приложение, настроить структуру каталогов с разделением на domain/application/infrastructure/web слои
- [x] 1.2 Docker Compose — настроить контейнеры для приложения, веб-сервера и базы данных
- [x] 1.3 Инструменты качества — подключить Pint, PHPStan, Rector, PHPCPD, Infection, настроить конфигурации
- [x] 1.4 CI-пайплайн — настроить GitHub Actions: lint, unit tests с coverage, phpstan, phpcpd, rector dry-run, composer audit
- [x] 1.5 Дополнительные CI workflows — настроить workflows для E2E, smoke tests, mutation tests

## Этап 2: Доменный слой

- [x] 2.1 Сущность User — доменная модель пользователя с валидацией
- [x] 2.2 Сущность Project — доменная модель проекта, правило владельца
- [x] 2.3 Сущность ProjectMember — модель членства, правило автоматического добавления владельца
- [x] 2.4 Сущность Task — доменная модель задачи со статусами (todo/in_progress/done) и приоритетами (low/medium/high)
- [x] 2.5 Сущность Comment — доменная модель комментария, правило доступа только для участников проекта
- [x] 2.6 Доменные правила и валидация — правила: создатель задачи — участник проекта, исполнитель — участник проекта, комментатор — участник проекта

## Этап 3: Аутентификация

- [x] 3.1 Миграции User — таблица users в БД (создана при init Laravel)
- [x] 3.2 Use case: регистрация — application service для регистрации нового пользователя
- [x] 3.3 Use case: вход и выход — application service для аутентификации и завершения сессии
- [x] 3.4 UI: страница регистрации — Blade-шаблон, форма, валидация
- [x] 3.5 UI: страница входа — Blade-шаблон, форма, редирект на Dashboard
- [x] 3.6 Middleware авторизации — защита маршрутов для авторизованных пользователей

## Этап 4: Проекты

- [x] 4.1 Миграции Project и ProjectMember — таблицы projects и project_members в БД
- [x] 4.2 Use case: создание проекта — application service, автодобавление владельца как участника
- [x] 4.3 Use case: список проектов пользователя — application service для получения проектов текущего пользователя
- [x] 4.4 UI: список проектов — Blade-шаблон, отображение проектов, кнопка создания
- [x] 4.5 UI: создание проекта — форма создания проекта с валидацией

## Этап 5: Задачи

- [ ] 5.1 Миграции Task — таблица tasks в БД
- [ ] 5.2 Use case: создание задачи — application service, проверка членства создателя в проекте
- [ ] 5.3 Use case: редактирование задачи — application service для обновления полей задачи
- [ ] 5.4 Use case: изменение статуса задачи — application service с валидацией переходов
- [ ] 5.5 Use case: назначение исполнителя — application service, проверка членства исполнителя
- [ ] 5.6 UI: страница проекта со списком задач — Blade-шаблон, список задач, фильтры по статусу
- [ ] 5.7 UI: создание и редактирование задачи — форма с полями: название, описание, статус, приоритет, дедлайн, исполнитель
- [ ] 5.8 UI: страница задачи — Blade-шаблон с отображением всех полей задачи

## Этап 6: Комментарии

- [ ] 6.1 Миграции Comment — таблица comments в БД
- [ ] 6.2 Use case: добавление комментария — application service, проверка членства автора в проекте
- [ ] 6.3 Use case: список комментариев задачи — application service для получения истории комментариев
- [ ] 6.4 UI: комментарии на странице задачи — отображение истории комментариев и форма добавления

## Этап 7: Dashboard и фильтрация

- [ ] 7.1 Use case: мои задачи — application service для получения задач, назначенных текущему пользователю
- [ ] 7.2 Use case: фильтрация задач — фильтрация по статусу и дедлайну в списке задач проекта
- [ ] 7.3 UI: Dashboard — задачи пользователя, задачи с ближайшим дедлайном, быстрые ссылки на проекты
- [ ] 7.4 UI: фильтры на странице проекта — фильтры по статусу и дедлайну в списке задач

## Этап 8: Качество и финализация

- [ ] 8.1 E2E тесты — покрыть сценарии: регистрация, вход, создание проекта, создание задачи, изменение статуса, список своих задач
- [ ] 8.2 Мутационные тесты — запустить Infection на domain и application слоях, зафиксировать базовый MSI
- [ ] 8.3 Coverage gate — убедиться что покрытие domain/application >= 80%, настроить ratchet
- [ ] 8.4 Финальный smoke test — docker compose up, проверка всех основных URL
- [ ] 8.5 Финальный review — полный периодический review по чеклисту из AGENTS.md секция 7
