# Минимальное описание интерфейса: TaskFlow

## 1. Общие принципы

- Интерфейс должен быть простым и понятным.
- Основной сценарий должен проходиться без лишних экранов.
- Для MVP допустим server-rendered UI без сложного frontend SPA.
- Визуальная часть должна быть минимальной, но аккуратной.

## 2. Экраны

### Гостевые экраны

- Страница входа
- Страница регистрации

### Основные экраны авторизованного пользователя

- Dashboard
- Список проектов
- Страница проекта со списком задач
- Страница задачи или форма редактирования задачи

## 3. Минимальное поведение экранов

### Dashboard

Показывает:

- задачи, назначенные текущему пользователю;
- задачи с ближайшим дедлайном;
- быстрые ссылки на проекты.

### Список проектов

Позволяет:

- увидеть доступные проекты;
- перейти в проект;
- создать новый проект.

### Страница проекта

Показывает:

- название проекта;
- список задач;
- фильтры по статусу;
- возможность создать задачу.

### Форма задачи

Позволяет:

- задать название;
- задать описание;
- выбрать статус;
- выбрать приоритет;
- указать дедлайн;
- назначить исполнителя;
- сохранить изменения.

### Страница задачи

Показывает:

- основные поля задачи;
- комментарии;
- форму добавления комментария.

## 4. Навигация

- После входа пользователь попадает на Dashboard.
- Из Dashboard пользователь может перейти к списку проектов.
- Из списка проектов пользователь может перейти в конкретный проект.
- Из проекта пользователь может перейти к созданию или просмотру задачи.

## 5. Решения, оставленные агенту

Агент может самостоятельно определить:

- точный layout страниц;
- использовать отдельную страницу задачи или модальную форму там, где это не конфликтует с простотой MVP;
- состав dashboard в пределах описанных целей;
- конкретные тексты кнопок и вспомогательных сообщений.
