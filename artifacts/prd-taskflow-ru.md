# PRD: TaskFlow

## 1. Идея продукта

TaskFlow — демонстрационный веб-проект для управления личными и командными задачами.

Продукт нужен как учебный, но реалистичный пример для работы автономного агента по workflow:

- анализ артефактов;
- построение Roadmap;
- декомпозиция задач;
- реализация через тесты и проверки.

## 2. Цель MVP

Дать пользователю возможность:

- зарегистрироваться и войти в систему;
- создать проект;
- создавать и редактировать задачи внутри проекта;
- отслеживать статус, приоритет и дедлайн задачи;
- видеть список своих задач и задач проекта;
- оставлять комментарии к задачам.

## 3. Роли

- Гость: может зарегистрироваться и войти.
- Пользователь: работает только со своими данными и проектами, в которых участвует.

Для MVP административная роль не требуется.

## 4. Основные пользовательские истории

- Как гость, я хочу зарегистрироваться, чтобы получить доступ к системе.
- Как пользователь, я хочу войти в систему, чтобы видеть свои проекты и задачи.
- Как пользователь, я хочу создать проект, чтобы группировать задачи.
- Как пользователь, я хочу создать задачу в проекте, чтобы зафиксировать работу.
- Как пользователь, я хочу указать задаче статус, приоритет и дедлайн, чтобы управлять исполнением.
- Как пользователь, я хочу редактировать задачу, чтобы обновлять её состояние.
- Как пользователь, я хочу комментировать задачу, чтобы фиксировать обсуждение.
- Как пользователь, я хочу видеть список задач проекта, чтобы понимать текущее состояние работ.
- Как пользователь, я хочу видеть отдельный список своих задач, чтобы быстро находить назначенное мне.
- Как пользователь, я хочу фильтровать задачи по статусу и сроку, чтобы фокусироваться на важном.

## 5. Функциональные требования MVP

- Регистрация нового пользователя.
- Аутентификация и завершение сессии.
- Создание проекта.
- Просмотр списка проектов текущего пользователя.
- Создание задачи внутри проекта.
- Редактирование задачи.
- Изменение статуса задачи.
- Изменение приоритета задачи.
- Установка и изменение дедлайна задачи.
- Назначение задачи пользователю.
- Просмотр списка задач проекта.
- Просмотр списка задач, назначенных текущему пользователю.
- Фильтрация задач по статусу.
- Фильтрация задач по дедлайну.
- Добавление комментариев к задаче.
- Просмотр истории комментариев задачи.

## 6. Нефункциональные требования

- Приложение должно быть пригодно для локальной разработки через Docker Compose.
- Кодовая база должна быть понятной для автономного агента и человека.
- Требуется покрытие unit и e2e тестами для ключевых сценариев MVP.
- Проект должен поддерживать автоматические проверки качества в CI.
- Архитектурные решения должны позволять развивать проект без жёсткой связности между слоями.

## 7. Границы MVP

Не входят в MVP:

- роли администратора и модератора;
- вложения к задачам;
- уведомления по email или в реальном времени;
- совместное редактирование;
- внешние интеграции;
- kanban board;
- публичные проекты;
- сложная система прав доступа.

## 8. Критерии успеха MVP

- Пользователь может пройти путь от регистрации до создания проекта и первой задачи.
- Пользователь может изменить статус и дедлайн задачи.
- Пользователь может увидеть свои задачи отдельным списком.
- Пользователь может оставить комментарий к задаче.
- Ключевые сценарии подтверждены тестами.
