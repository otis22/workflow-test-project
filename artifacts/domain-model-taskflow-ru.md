# Доменная модель: TaskFlow

## 1. Сущности

### User

- id
- name
- email
- password_hash
- created_at
- updated_at

### Project

- id
- owner_id
- name
- description
- created_at
- updated_at

### ProjectMember

- id
- project_id
- user_id
- created_at

Для MVP достаточно хранить факт участия пользователя в проекте без сложных ролей.

### Task

- id
- project_id
- creator_id
- assignee_id
- title
- description
- status
- priority
- due_date
- created_at
- updated_at

### Comment

- id
- task_id
- author_id
- body
- created_at

## 2. Связи

- Один пользователь может владеть многими проектами.
- Один проект может иметь много участников.
- Один проект может иметь много задач.
- Одна задача принадлежит одному проекту.
- Одна задача может быть назначена одному пользователю или быть без исполнителя.
- Одна задача может иметь много комментариев.

## 3. Базовые правила домена

- Проект должен иметь владельца.
- Владелец проекта автоматически является его участником.
- Задача всегда принадлежит проекту.
- Создатель задачи должен быть участником проекта.
- Исполнитель задачи, если указан, должен быть участником проекта.
- Комментарий может добавить только участник проекта.

## 4. Статусы задач

Для MVP используются статусы:

- `todo`
- `in_progress`
- `done`

Агент может предложить уточнение переходов между статусами, если это потребуется в реализации.

## 5. Приоритеты задач

Для MVP используются приоритеты:

- `low`
- `medium`
- `high`

## 6. Неопределённости, оставленные на решение агента

Агент может принять решение по:

- способу хранения членства в проекте;
- наличию soft delete;
- формату описаний и ограничений длины полей;
- деталям валидации дедлайна;
- отображению истории изменений задачи.
